# Caseworker Task Manager

A small, full-stack task-management application built for the [HMCTS DTS Developer Technical Test](https://github.com/hmcts/dts-developer-challenge). It gives caseworkers one place to create, review, prioritise and complete their tasks.

## Features

- Create tasks with a title, optional description, workflow status and due date/time.
- View all tasks, or filter them by status; search by title and description.
- Update task details and status, including a dedicated status endpoint.
- Delete tasks with a confirmation step.
- At-a-glance totals for all, to-do, in-progress and completed tasks.
- Due-date labels that make overdue work easy to spot.
- SQLite persistence, input validation and consistent API error responses.
- Interactive API documentation at `/docs` and an automated test suite.
- Responsive interface with keyboard-friendly controls and labelled form fields.

## Technology choices

| Area | Technology | Reason |
| --- | --- | --- |
| API | Python, FastAPI, Pydantic | Typed request/response models, validation and generated OpenAPI documentation |
| Data access | SQLAlchemy 2 | Explicit model and session management |
| Database | SQLite | Persistent local database with no separate database server required |
| Frontend | HTML, CSS and vanilla JavaScript | Lightweight, responsive UI without a frontend build step |
| Tests | pytest and FastAPI TestClient | Exercises API behaviour using an isolated in-memory database |

## Requirements

- Python 3.11 or newer
- pip

## Run locally

```bash
# 1. Create and activate a virtual environment
python -m venv .venv

# macOS / Linux:
source .venv/bin/activate

# Windows PowerShell:
# .venv\Scripts\Activate.ps1

# 2. Install dependencies
python -m pip install -r requirements.txt

# 3. Start the application
python -m uvicorn main:app --reload
```

Open **http://127.0.0.1:8000** for the application and **http://127.0.0.1:8000/docs** for the interactive API reference. The first run creates `tasks.db` in the project directory. The database file is excluded from Git.

To use a different database location, set `DATABASE_URL`, for example:

```bash
# macOS / Linux
export DATABASE_URL="sqlite:///./data/casework.db"
python -m uvicorn main:app --reload
```

## Run the tests

```bash
python -m pytest
```

The tests use an in-memory SQLite database, so running them does not alter your local task data.

## API reference

All endpoints are prefixed with `/api` and exchange JSON.

| Method | Endpoint | Description | Success |
| --- | --- | --- | --- |
| `GET` | `/api/health` | Health check | `200 OK` |
| `POST` | `/api/tasks` | Create a task | `201 Created` |
| `GET` | `/api/tasks` | List tasks, optionally filtered with `?status=todo` | `200 OK` |
| `GET` | `/api/tasks/{id}` | Retrieve one task | `200 OK` |
| `PATCH` | `/api/tasks/{id}` | Update one or more task fields | `200 OK` |
| `PATCH` | `/api/tasks/{id}/status` | Update only the task status | `200 OK` |
| `DELETE` | `/api/tasks/{id}` | Delete a task | `204 No Content` |

### Task fields

| Field | Type | Rules |
| --- | --- | --- |
| `id` | integer | Generated by the database |
| `title` | string | Required, 1–120 characters after trimming whitespace |
| `description` | string or `null` | Optional, maximum 2,000 characters |
| `status` | string | `todo`, `in_progress` or `completed`; defaults to `todo` |
| `due_at` | ISO-8601 datetime | Required and must include a timezone offset |
| `created_at` | ISO-8601 datetime | Generated by the API in UTC |
| `updated_at` | ISO-8601 datetime | Generated by the API in UTC |

Date/time values are normalised to UTC and returned with a `Z` suffix. The browser converts the selected local date/time to UTC before sending it to the API.

### Example: create a task

```bash
curl -X POST http://127.0.0.1:8000/api/tasks \
  -H "Content-Type: application/json" \
  -d '{
    "title": "Review case bundle",
    "description": "Check the latest documents before the hearing.",
    "status": "todo",
    "due_at": "2030-05-01T09:00:00+01:00"
  }'
```

### Example: update status

```bash
curl -X PATCH http://127.0.0.1:8000/api/tasks/1/status \
  -H "Content-Type: application/json" \
  -d '{"status": "in_progress"}'
```

### Error responses

Errors use a consistent envelope. A missing task returns `404`:

```json
{
  "error": {
    "code": "not_found",
    "message": "Task 123 was not found"
  }
}
```

Invalid request data returns `422` with field-level details:

```json
{
  "error": {
    "code": "validation_error",
    "message": "Please check the submitted task details.",
    "details": [
      { "field": "title", "message": "..." }
    ]
  }
}
```

## Design notes and scope

- The application is a focused technical-test implementation. Authentication, role-based access, multi-user tenancy and deployment infrastructure are outside the supplied brief.
- SQLite is appropriate for a self-contained demonstration. A production service with concurrent users would normally use a managed relational database such as PostgreSQL.
- The API requires timezone-aware due dates to avoid silently interpreting ambiguous timestamps. The interface sends the browser's local selection as an explicit UTC instant.
- The frontend and API are served from the same FastAPI application, avoiding cross-origin configuration for local development.
- The UI is intentionally dependency-light; no Node.js toolchain or frontend build is needed.
